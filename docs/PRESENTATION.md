# Aperture: презентация и речь докладчика

Семь слайдов, ориентир речи 2 минуты. Основная версия: [presentation.html](presentation.html).

Aperture объединяет рынок AI-моделей и compute-задач с разрешениями владельца. Один gateway направляет модельные запросы к настроенным провайдерам, Python-вычисления — authenticated workers, а многошаговые data workflows восстанавливаются из журнала и возвращают подписанные результаты.

## Речь по слайдам

### 1. AI-инференс и рынок вычислений (0:00–0:15)

Aperture соединяет модельные запросы и compute workers через один task gateway. Владелец задаёт разрешение агенту и предел расходов до запуска; worker возвращает файлы и подписанные сведения о выполнении. Данные могут оставаться вне контекста LLM. Сегодняшняя версия объединяет CPU workers и настроенные оператором model offers; Solana Devnet используется только при готовой конфигурации канала.

### 2. Делегирование вместо прямого скрипта (0:15–0:30)

Наш ключевой сценарий: владелец поручает агенту аналитику по CSV. Ему важно ограничить доступ и расходы, продолжить работу после сбоя и проверить целостность файлов. Aperture связывает эти шаги в одном процессе: выбранные CSV не добавляются в prompt автоматически, расходы ограничены подписанными условиями, а принятые задачи можно восстановить без слепой повторной отправки. Gateway и worker обрабатывают выбранные данные и остаются частью доверенной среды.

### 3. Маршрут и разрешение задачи (0:30–0:50)

Владелец выбирает маршрут: модельный запрос, Python-задачу или data workflow. Он проверяет точный запрос или исходный код и пределы расходов до dispatch. В browser flow каждый workflow-шаг подписывается отдельно; SDK/MCP может передать заранее известный план в рамках общей политики. Журнал хранит принятые шаги для восстановления.

### 4. Отчёт готов. Повторных задач нет. (0:50–1:15)

Мы проверили этот путь на семнадцати тысячах синтетических строк. Прервали выполнение после принятия первой задачи, затем восстановили его с прежним журналом. Завершились ровно пять задач, без дубликатов. Все три файла совпали с прямым расчётом Python. Полный сценарий занял около восьми секунд на одном компьютере. Это локальный результат без Docker и платежей Solana.

### 5. Solana ограничивает затраты (1:15–1:35)

Solana отвечает за паспорт агента и правила расчёта в платёжном канале. Владелец делегирует доступ отдельному ключу, задаёт ограничения и может отозвать паспорт. Протокол ограничивает списание и защищает от повторного расчёта одной задачи. Подписанные квитанции связывают результат с разрешением, но сами по себе не доказывают правильность удалённого вычисления.

### 6. MCP и Python SDK для агента (1:35–1:50)

Мы ориентируемся на разработчиков AI-агентов, которым нужно совместить model inference, повторяемые compute jobs и data workflows. Агент подключается через MCP или Python SDK; gateway связывает выбранный model offer или worker с разрешением задачи. Провайдеры моделей пока настраиваются оператором; автоматические выплаты им ещё не реализованы.

### 7. Единый gateway, ранний рынок (1:50–2:00)

Локальный MVP уже объединяет модели, CPU compute и восстанавливаемые workflows под одним разрешением задачи. Следующий этап — пилоты, проверка онбординга независимых провайдеров и аудит. GPU-сеть и автоматические выплаты требуют отдельной реализации и проверки.

## Границы заявлений

- Стандартный локальный preview запускает доверенные шаблоны на хосте без Docker-изоляции.
- Docker-режим реализован отдельно; для задач настроены 1 CPU, 512 MiB и отключённая сеть. Этот прогон не проверял Docker.
- Отдельный сохранённый запуск завершился с расчётом в 3 200 lamports и on-chain TaskReceipt. На 05.10.2026 официальный Devnet RPC и независимый публичный Devnet RPC подтвердили одинаковый genesis hash и finalized-статус той же транзакции. Read-only preflight подтвердил развернутую программу и ProtocolConfig v2; перед записью повторить readiness, если Devnet перезапускался.
- Подписи подтверждают авторство квитанций и целостность данных. Они не доказывают правильность вычисления удалённым исполнителем.
- Датасеты можно держать вне промпта. Владелец выбирает результаты и логи, которые передаёт модели; шлюз и worker имеют доступ к обрабатываемым данным.
- Котировка фиксирует тариф и потолки суммы/времени. Фактическая длительность не известна заранее.
- Успешные тесты не означают 100% покрытия.
- GPU, независимые операторы и Mainnet остаются планами. Подтверждённые пилоты, партнёры и сроки не заявлены.

## Показ презентации

Откройте HTML напрямую или по адресу `/presentation.html` запущенной консоли. HTML не загружает внешние шрифты и не опрашивает gateway. Храните рядом `aperture-mark-v3.png`, `Roboto-Variable.ttf`, `Roboto-OFL.txt` и `presentation-evidence.json` для автономного просмотра.

- Стрелки, Space, PageUp/PageDown: переключение слайдов. На сенсорных экранах доступен горизонтальный свайп.
- Цифры 1–7: переход к выбранному слайду. Home/End: первый или последний слайд.
- N: заметки докладчика; Escape: закрыть.
- F: полный экран, если браузер его разрешает.
- T: запуск и пауза таймера питча.
- R (или двойной клик по таймеру): сброс таймера на 0:00.
- D (или кнопка «Тема» в панели): переключение светлой и тёмной темы Material 3 (синхронизируется с системной темой и консолью).
- P (или «Печать / PDF»): все семь слайдов в альбомном формате (всегда выводится на чистом светлом фоне).
- На смартфонах используется адаптивная вертикальная компоновка.
